# ADR-027: Manual points adjustment

- **One ledger path.** `loyalty.services.adjust` writes the ledger row (`reason=adjustment`, plus new nullable `admin`, `category`, `note` columns) and updates the account summary in one transaction under the account's row lock. Because the summary always equals the ledger (`balance == lifetime_earned == sum(delta)`, which the nightly reconciliation asserts), an adjustment moves both by `delta`, like a reversal does. Positive adjustments get a 365-day expiry and `remaining`; negative ones have neither. Customers see the row in `/users/me/points/transactions` (category only; the admin's note stays internal).
- **Below zero.** A negative adjustment cannot take the balance below zero (422 `insufficient_points`) unless the category is `fraud_reversal`, where reclaiming points that were already spent legitimately leaves a negative balance that future earnings pay off.
- **Idempotency.** `Idempotency-Key` (1-64 characters, required) is scoped to the admin; the ledger reference is `admin_id:sha256(key)[:40]` so the existing unique `(reason, reference_type, reference_id)` constraint makes a repeat a no-op. A repeat with the same body returns the original row (200, `replayed: true`, no second audit entry, no limit check); the same key with a different body is 409 `idempotency_conflict`.
- **Limits.** `|amount|` must be 1..`POINTS_ADJUST_MAX` (10,000) and the sum of an admin's `|amount|` per Karachi day may not exceed `POINTS_ADJUST_DAILY_LIMIT` (50,000): 403 `daily_limit_exceeded`. The admin's own user row is locked during the check, so two parallel requests cannot jointly exceed it. Both values move into platform settings in Step 9.
- **Targets**: accounts with role customer or business owner (owners keep customer abilities), active or suspended; admins, staff and deleted accounts are 422.
- **Endpoints**: `adjust` needs `points.adjust` plus a recent re-authentication; `adjust/preview` and `adjustments` need the permission only (no writes). Preview reports the current and resulting balance, `allowed`, the problems found and the day's usage. Each adjustment writes exactly one audit entry with the balance before/after, delta, category, note and ledger id.
