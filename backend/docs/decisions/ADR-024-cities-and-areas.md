# ADR-024: City and area administration

- **Visibility.** `hidden` cities are used by nobody (not registrable, not searchable). `preview` cities are invisible to the public but **visible on the public search and business-page endpoints to any authenticated admin** (`optional_user` + `geo.preview_cities()`, a context variable set only around those two calls, never a query parameter). Customers and owners get exactly the public view. An inactive city is hidden from everyone.
- **Versions.** `City.version` and `Area.version` (new columns) are required on every `PATCH` and bumped on each change (409 `stale_version`).
- **Deactivation guard.** Switching a city or area off while it has *listed* businesses is 409 `has_active_listings` (the count is in `fields`). `force=true` needs `geo.manage` plus a recent re-authentication; it then notifies each affected owner (`onboarding_status_changed`, status "hidden") and records `hidden_listings` in the audit entry. No listing rows are changed: the public query already excludes inactive places, so reactivating restores them with no state to remember. Changing `visibility` is not guarded because it is reversible.
- **Polygons** are GeoJSON `Polygon` only: closed rings, coordinates in range, GEOS-valid (no self-intersection), at most 5000 points; an explicit empty/invalid object is a 422, `null` clears it.
- **Slugs** follow the taxonomy rules; a city slug is globally unique, an area slug unique per city (generated with a numeric suffix when omitted, 409 `slug_taken` when explicit and taken).
- **CSV import** (`name,slug,lat,lng,is_pilot`; UTF-8 with or without BOM; <= 1 MB and 2000 rows; 10 imports per hour per admin): every row is validated first (row 1 is the header, so data starts at row 2) for name, slug format, duplicates inside the file and against the city, coordinates and the pilot flag. Any bad row means nothing is created and the 422 `csv_invalid` response lists every problem under `fields["row N"]`. A successful import is one audit entry.
