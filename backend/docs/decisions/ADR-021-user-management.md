# ADR-021: Admin user management

- **Cross-app access.** `backoffice` never imports other apps' models. Each owning app exposes what the admin side needs in an `adminops.py` module (accounts, businesses, bookings, loyalty, notifications) or its selectors (reviews); the backoffice services orchestrate them in one transaction and write the audit entry.
- **Suspension.** `POST /admin/users/{id}/suspend` (`users.suspend` + recent re-authentication, reason required): status `suspended`, every refresh-token family revoked (the bearer tokens stop working at once), owned businesses unlisted. A `SuspensionRecord` stores the reason, the admin and `{business_id: was_listed}`. Reactivation restores exactly that: a business that was unlisted before stays unlisted, and a listed one is only relisted while it is still `verified`. Only one open suspension per user (DB constraint).
- **Bookings are kept** (no automatic cancellation). A suspended customer's businesses are told about their upcoming bookings (`customer_suspended_notice`); a suspended owner's customers with upcoming bookings are told the business is unavailable (`business_suspended_notice`). They can cancel themselves or contact support.
- **Admin accounts.** Only a super admin may act on an admin account (suspend, force logout, reset); nobody may suspend or regroup themselves; the last active super admin can be neither suspended nor demoted (409 `last_super_admin`, checked after the role guard so a non-super gets 403). Admin accounts are created without a password and receive a reset link; a group maps to a role (`super_admin` group = `super_admin` role, the others = `admin`).
- **Password reset** only emails a one-time link; the admin never sees or sets a password. **Force logout** revokes every session.
- **Deletion requests** are processed by anonymising: email becomes `deleted-<uuid>@deleted.invalid`, phone is cleared, the password is made unusable, the profile is reset to "Deleted user" (photo file deleted after commit), wishlist and one-time tokens are removed, sessions revoked, free-text contact on the user's appointments and stored notification recipients are blanked. Appointments, reviews and the points ledger keep pointing at the (now anonymous) user so history and totals stay valid. Accounts that still own businesses are refused (409 `owner_has_businesses`). The audit entry records only booleans (`had_phone`, `had_email`), never the data itself. Processing needs `users.suspend`.
- **Lists**: limit/offset with `total`; `sort` must be a key of an allow-list (never passed raw to `order_by`). Search covers name, email, phone (any suffix of 3+ digits), numeric id and public id.
